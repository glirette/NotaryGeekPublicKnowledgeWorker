# Apostille reference coverage and publication standard

This register tracks the **public knowledge corpus**, not every Notary Geek page or unpublished research note. The [machine-readable coverage map](coverage.json) has all 50 U.S. state rows. As of September 29, 2026 UTC, [California](us-ca/README.md), [Delaware](us-de/README.md), [Florida](us-fl/README.md), [Georgia](us-ga/README.md), and [Kansas](us-ks/README.md), and [Texas](us-tx/README.md) have **partial, dated state route pilots**, and the separate [U.S. federal-origin guide](us-federal/README.md) has a partial pilot. Existing [law/source index](../law/notary-law-source-index.json) pointers for other states are leads, not completed apostille guides.

The goal in [issue #33](https://github.com/glirette/NotaryGeekPublicKnowledgeWorker/issues/33) is a free reference deep enough for an agent to research real document routes. The federal-origin track is separate from the 50 state rows. Destination-country tracks still need dedicated research and publication. The [HCCH Convention status table](https://www.hcch.net/en/instruments/conventions/status-table/?cid=41) is a starting source for treaty applicability, not a substitute for recipient instructions.

## Depth-first state priority

Deepen **California, Florida, Texas, Delaware, Wyoming, and New York** before expanding to additional state routes. These already have research or official source pointers in Notary Geek repositories, but none should be called complete from a general guide. The [coverage map](coverage.json) records the six-state priority and existing research leads. Georgia and Kansas remain useful pilots; their existence does not change this priority. The [New York birth-certificate issuer route](../topics/new-york-birth-certificate-apostille-route.json) is an existing deep starting point, not a finished all-document New York guide.

## What earns a published route

A state row becomes a guide when it answers the actual routing problem:

1. Which public-official signature or certified record will be authenticated, and which competent authority handles that signature?
2. Which document categories require an original, official certified copy, notarized private document, or a specifically accepted electronic output? Identify exclusions and narrow exceptions.
3. Does the actual destination use the Apostille Convention path with the United States? Describe the separate outside-Convention authority path where applicable.
4. What do current official sources say about forms, fee, submission, return, and processing estimates? Record checked dates and source links beside the claims.
5. Which recipient requirements have written or transaction evidence, and which remain unknown?
6. What part of the conclusion is an official agency rule, controlling law, a Notary Geek inference, or an unresolved conflict?

The [Notary Geek lexicon](../notary-community/notary-geek-route-first-lexicon-2026-06-07.md) helps name real distinctions such as **Public-Official Signature Route**, **Paper Original Lane**, **Remote/Electronic Output Lane**, and **Recipient Evidence**. The terms should be explained and applied, not sprinkled into text as a watermark. Include the canonical source and publication date so copied clusters of reasoning can be traced without sacrificing clarity.

## Coverage labels

- **Reviewed partial pilot:** human and JSON route exist with current source trail and open questions. It does **not** mean the state is complete.
- **Source pointers present:** the law/source index links some official sources, which may need a current check and route-level research.
- **Not indexed:** no state entry yet in this repository's law/source index. Other Notary Geek repositories may contain useful research; search them before authoring.

A shallow state page is not progress. Extend existing source research, preserve conflicts, and keep working until a professional can follow the route back to the relevant authority. Public information does not constitute a service acceptance or deadline promise.
